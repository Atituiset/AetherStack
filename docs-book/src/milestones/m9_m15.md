# 里程碑历程: M9 → M15

> 后半程目标（`docs/m9_plan.md`）：除真实射频硬件外，补齐与真实 3GPP 系统
> 的本质差距——可靠性、同步、多用户、安全、可靠传输、移动性、核心网解耦。
> 每步保持项目哲学：简化但不失真、可测、可观测。

## M9 FEC + HARQ — 链路可靠性 (2026-08)

位置: `stack/phy/{fec.cpp,include/phy/fec.h}`、`stack/core/{harq.cpp,include/core/harq.h}`

| 设计点 | 实现 |
|--------|------|
| 信道编码 | 卷积码 K=7，生成多项式 G1=133o / G2=171o（NASA 标准），尾比特归零收尾；硬判决 Viterbi 译码 + 回溯 |
| 完整性 | CRC16-CCITT 附着传输块；CRC 失败不递交上层（坏块不再穿透） |
| HARQ | 停等式多进程（4 进程轮转），7 字节帧头 `[proc][ndi][rv][len][info_len]`；ACK/NACK 作为 LCID 60 控制 PDU 走对向 DATA 帧；超时/NACK 重传同一编码块，RX 侧 Chase 合并（逐比特多数表决） |

**效果**：30% 帧级丢弃 + 比特翻转混合注入下应用层零错误递交；20% 信道丢包场景从"有损"变"无损"。

## M10 同步与导频 — 小区搜索 (2026-08)

位置: `stack/phy/include/phy/sync.h`

前导突发布局 `[CP][PSS][CP][SSS][CP][DMRS][CP][data…]`：

* **PSS**：Zadoff-Chu 根序列（3 个 NID2），滑动相关得到定时偏移
* **SSS**：第二 ZC 根（NID1），补全 PCI = NID1×3 + NID2
* **DMRS**：由完整 PCI 导出的已知 QPSK 参考符号，最小二乘信道估计 + PCI 确认

UE 从此"知道自己在跟谁说话"；gNB 的 `pci` 进入 SIB1 广播，为 M11 多小区与 M14 移动性奠基。

## M11 调度器 + 多 UE (2026-08)

位置: `stack/core/src/bs_node.cpp`（DlFlow / schedule_downlink）

* 每 UE 独立下行流（自己的 HARQ 实体 + 队列），公平轮转：每流每 tick 至多提交一个新传输块，HARQ in-flight ≥ 4 时让路
* 上行保持 grant-free（配置授权语义）；只有共享下行需要调度
* 队列背压上限 `max_dl_queue_per_ue`，溢出丢最旧并计数

E2E：两 UE 并发附着 + 各自业务互不干扰。

## M12 安全 — 鉴权与加密 (2026-08)

位置: `stack/common/include/common/crypto.h`、NAS/PDCP 层

| 能力 | 实现 |
|------|------|
| 订阅鉴权 | HMAC-SHA256 AKA：HSS 注册 USIM 主键 → AUTH_REQUEST(RAND) → RES=HMAC(K,RAND) 校验；未知 IMSI 保留开放接入路径（测试用） |
| 会话密钥 | session_k = HMAC(K, RAND ‖ "up-enc")，鉴权成功后交付 gNB |
| 机密性 | ChaCha20（RFC 8439），PDCP flags bit0 加密位，nonce=PDCP seq |

错密钥 UE 被拒于 REGISTERED 之外；正确密钥全程加密回环。

## M13 RLC UM/AM + PDCP 完整性 (2026-08)

位置: `stack/rlc/include/rlc/rlc_am.h`

* RLC AM：发送窗口 + 接收重排序窗，窗外 SN 记洞触发 STATUS；T_poll 静默探测重传；STATUS PDU 携带 ACK_SN + 位图 NACK
* 长包分段（T-PDU 上限）+ 重组
* PDCP MAC-I 完整性（M13 一并落地）

长业务在无损链路上零丢失、有序递交；乱序/丢块由 ARQ 自愈。

## M14 移动性 (2026-08, commit 76e9f1b)

位置: `docs/m14_plan.md`

| 子系统 | 设计 |
|--------|------|
| 测量报告 | SIB1 扩展 cell_id/plmn/tac；UE 按 SIB 接收次数维护邻区强度，周期上报 `[n]{cell,strength}`；gNB 仅当服务小区从报告中消失且邻区可闻时触发 HO（防乒乓） |
| 切换 | X2-like `HoCoordinator` 回调 + `HoContext{tmsi,imsi,up_key,sec_on}`；目标预留上下文分配新 C-RNTI，flow/AM 实体随迁，NAS 注册保持 |
| 寻呼 | paging 记录搭 SIB 广播下行（LCID_PAGING）；空闲 UE 比对 IMSI 自动 service request |
| RLF | CONNECTED 态专用下行静默超时 → 重建立（MSG3 带 REESTABLISHMENT_REQUEST）；有上下文则迁移数据面，无上下文回退全量 attach |

四个新 E2E：双小区切换、寻呼、RLF 重建立保 NAS、gNB 重启回退恢复。
过程中修正的深层缺陷：RLF 看门狗曾把 SIB 广播算作"链路存活"，导致 gNB 重启后永远检不出无线链路失败——改为只认专用下行。

## M15 核心网进程分离 (2026-08, commits 3337f01 / 751ba63)

位置: `stack/cn/`（新库）、`docs/m15_plan.md`

把内嵌在 gNB 里的假 MME 拆成真正的核心网实体：

```
UE ──空口── gNB ──NG-like(UDP)── amfd          控制面：HSS/AKA/TMSI/会话密钥
                 ──GTP-U-like(UDP)── upfd      用户面锚点：{tmsi→rnti,cell} 路由表
```

| 组件 | 内容 |
|------|------|
| CnMessage | 统一二进制信封 `[type:1][len:2 LE][value]`，NG 族（NG_SETUP/UPLINK_NAS/DOWNLINK_NAS/SESSION_KEY/HO_*）与 GTP-U 族（UL/DL_DATA/PATH_SWITCH） |
| CnLink | 抽象载体：InMemoryCnLink（多 peer 扇出，测试用）/ UdpCnLink（client 固定远端、server reply-to-last-sender） |
| Amf | HSS 订阅者库 + M12 鉴权全语义 + TMSI 分配；鉴权后 SESSION_KEY 下发 gNB，gNB 不再持有订阅者长期密钥 |
| Upf | 用户面锚点：上行数据学习路由，下行按 serving gNB 转发；切换 = PATH_SWITCH 表项更新，锚点与应用流不动 |
| BsNode | `attach_core()` 接线后 NAS 对 gNB 透明（UPLINK/DOWNLINK_NAS 隧道）；不接线保持旧行为，140 个旧测试零破坏 |
| 进程 | `amfd` / `upfd` 薄壳 + `bs --amf-addr --upf-addr`；4 进程冒烟 `tools/test_scripts/e2e_smoke_m15.py` |
| AMF 仲裁切换 | HO_REQUIRED → HO_COMMAND（目标 prepare 分配 C-RNTI）→ HO_NOTIFY → HO_PREPARED（源通知 UE）→ HO_COMPLETE → UE_CTX_RELEASE；X2 直连不再是必需路径 |

**价值验证**：gNB 重启后 AMF 注册表与 UPF 路由存活，UE 经 RLF→重建立失败→全量 attach 恢复，数据路径经锚点无缝续流。

**过程修复**：UPF 回程 handler 漏注册（DL_DATA 静默丢弃）、HO_PREPARED 漏带目标小区号（源无法匹配 pending HO）、RLF 看门狗广播误判（见 M14）。
