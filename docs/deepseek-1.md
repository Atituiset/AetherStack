## 一、无线系统实现的技能分层框架

为了能让 agent 自主推进，不能直接丢给它一句“写个 5G 协议栈”。必须把整个工程拆解成 agent 能理解、能执行、能自检的技能单元。

我建议采用 **四层技能模型**：

```
┌─────────────────────────────────────────────┐
│  场景/流程技能：整系统集成、用例编排           │
├─────────────────────────────────────────────┤
│  协议层技能：NAS / AS / L1 各子层实现          │
├─────────────────────────────────────────────┤
│  领域基础技能：信号处理、协议模板、PDU编解码    │
├─────────────────────────────────────────────┤
│  环境工具技能：编译/测试/仿真/日志/版本管理     │
└─────────────────────────────────────────────┘
```

### 1. 环境工具技能（最底层）
这是 agent 的“手脚”，让它能真正执行和验证代码。

- **构建系统技能**：CMake / Makefile 编写，交叉编译，依赖管理。
- **仿真与测试技能**：调用物理层仿真器（如 MATLAB/Python 信道模型）、协议测试桩（TTCN-3 或自制 stub）、单元测试框架（Google Test）。
- **日志与追踪技能**：可回溯的二进制/文本日志，用于 agent 自我排查。
- **版本与文档技能**：Git 操作、自动生成接口文档（Doxygen）。

### 2. 领域基础技能（通用原子能力）
这些是跨层、跨模块都会被复用的“知识性技能”。

- **L1 基础**：信道编码（LDPC/Polar）、调制（QPSK/64QAM）、OFDM 符号生成、MIMO 预编码算法。
- **协议通用基础**：ASN.1 / 非结构化 TLV 编解码器生成技能，状态机引擎（State Machine DSL 或代码骨架），消息队列/环形缓冲技能。
- **数据处理**：比特/字节序处理，CRC 计算，加密/完整性保护算法（SNOW 3G、AES、ZUC）。

### 3. 协议层技能（各子层模块）
将每一层进一步细分为“子技能”，以 **AS 层**为例：

- **L1 技能**：OFDM 调制解调、信道估计、物理信道映射（PDSCH/PDCCH）、功率控制。
- **MAC 技能**：调度器（PF/Round Robin）、HARQ 状态机、随机接入过程、逻辑信道优先级处理。
- **RLC 技能**：TM/UM/AM 实体，分段/重组，ARQ 重传。
- **PDCP 技能**：头压缩（ROHC）、加密/完整性保护、按序递交和重复检测。
- **RRC 技能**：系统消息广播、连接建立/释放、测量报告、移动性控制。
- **NAS 技能**：移动性管理（MM：附着/去附着，位置更新），会话管理（SM：PDU 会话建立）。

> **关键设计原则**：每个子技能必须**有清晰可测的接口**（比如输入一个 SDU，输出一个 PDU），这样 agent 可以先写接口契约，再实现。

### 4. 场景/流程技能（集成与编排）
这一层让 agent 把上述技能串成可运行的用例。

- **初始接入流程**：小区搜索 → 系统消息接收 → 随机接入 → RRC 连接 → NAS 附着。
- **数据传输流程**：上行/下行数据在 NAS→PDCP→RLC→MAC→L1→信道→L1→… 全链路跑通。
- **移动性流程**：基站间切换（含 Xn 接口模拟）。

## 二、如何用 Claude Code 按这个分层驱动系统实现

Claude Code 这类 agent 目前最适合 **“给定上下文 + 分步指令 + 自检验证”** 的工作方式。你可以这样设计工程推进策略：

### 第 0 步：建立“技能库”（Skill Library）
为每一层技能编写**技能卡片（Skill Card）**，放在工程的 `.skills/` 目录下，Claude Code 会原生读取。

示例技能卡片 `.skills/l1_ofdm_modulation.md`：
```markdown
# Skill: L1 OFDM 调制
- 输入：复数符号序列，长度 N_sc，IFFT 点数 N_fft，CP 长度
- 输出：时域 IQ 采样序列（float数组）
- 验证方法：调用 Python 参考模型，对比互相关峰值
- 依赖技能：无（基础算法）
- 实现语言：C（用于嵌入式）
- 接口定义文件：l1/ofdm_mod.h
```

每张卡片都给 agent 明确的上下文和目标，这样它不会凭想象乱写。

### 阶段 1：搭建骨架与最底层技能
让 Claude Code 依序完成：
1. 生成项目结构（build system、目录树）。
2. 实现 **环境工具技能**（编译脚本、单元测试框架接入、仿真环境 stub）。
3. 实现 **领域基础技能**（CRC、编解码、状态机引擎），每写一个就编译测试。

> 指令示例：“根据 `.skills/` 下的 crc.md，实现 CRC24 并跑通测试。”

### 阶段 2：自底向上逐个实现协议层技能
严格按照 **先 L1 → 再 MAC → RLC → PDCP → RRC → NAS** 的顺序。

每个子层的实现步骤：
- 先让 agent 阅读该子层的接口需求（你提前定义好头文件）。
- 让它生成实现。
- 让它同时生成 **单元测试** 和 **仿真验证脚本**。
- 编译、运行测试，若失败则让它根据日志自动修复（Claude Code 可循环）。

> **关键技巧**：每一层提供“桩（stub）”下层实现，让上层可以先跑逻辑。例如在实现 MAC 时，L1 可以用一个加噪声/延迟的信道模型桩代替真实物理层，这样 agent 可以独立验证 MAC 调度。

### 阶段 3：横向集成与场景流程验证
当所有层单测通过后，进入 **场景技能** 阶段。你可以给 agent 下达高层次指令：

“用初始接入流程集成测试：调用现有的 RRC、MAC 和 L1 技能，模拟 UE 从开机到 RRC 连接态的全流程，以 NAS 附着成功作为通过准则。”

此时 agent 会调用它之前建立的各层技能，编写集成测试代码。如果中间某个消息格式不对，它会回到相应层技能去修改——这形成了**自修复闭环**。

## 三、保证“AI 能自行实现”的 5 个关键成功要素

1. **接口设计先行**
   在写任何代码前，由你（人工）和 agent 一起定好所有子层间的 C 接口（或 Python/C++ 接口）。这些接口就是技能的“契约”。以后 agent 实现技能时，只需满足接口即可，你不必反复审阅内部细节。

2. **双模式参考实现**
   对于 L1 算法，让 agent 用 Python 写一版黄金参考模型，再用 C/C++ 写目标实现。Claude Code 可以运行 Python 参考模型输出预期结果，自动比对 C 实现输出，极大减少人工调试。

3. **利用 DSL 描述协议流程**
   对于 RRC、NAS 这类状态机密集型层，不要让它硬编码。可以先让 agent 写一个**协议流程描述语言（如用 YAML 定义状态、事件、转换）**，再生成代码。技能卡片里可包含“状态机生成器”技能。

4. **上下文切割**
   单次对话 Claude Code 承载不下整个系统。所以要按技能卡片和阶段分治。每张卡片一次只关注一个技能，保证上下文清爽。agent 每完成一个技能，更新测试报告和接口文档，下一个技能只需关心上游接口。

5. **自动化质量门槛**
   为每个技能定义明确的“完成定义”（DoD）：
   - 代码编译零警告
   - 单元测试覆盖 > 90%
   - 与 Python 参考模型输出一致（L1）
   - PDU 编解码与 Wireshark/TTCN 解码结果一致
   Claude Code 可在循环中不断查日志、修代码，直到满足这些条件。

## 四、示例：怎么让 Claude Code 实现 “MAC 随机接入过程”

假设你已经有了 L1 基础技能和 PHY 桩，现在要它实现 MAC 层的随机接入。你可以这样交互：

1. **给出技能卡片**：`mac_rach.md` 定义输入（来自 RRC 的 RACH 配置）、输出（RA-RNTI、Timing Advance）、协议状态机（基于 38.321）。
2. **任务指令**：“实现 MAC 层的基于竞争的随机接入过程，状态机用我们之前的 YAML 状态机引擎，MSG1 发送依赖 `l1_prach_tx` 技能，MSG2 接收解析依赖 `l1_pdcch_decode` 和 `mac_pdu_decode` 技能。完成后编写测试：模拟正常四步接入成功，以及冲突回退两种情况。”
3. agent 会依次：
   - 检索 `.skills/` 下的相关技能，
   - 生成 YAML 状态机描述，
   - 生成 C 代码，
   - 生成 mock 测试桩和测试用例，
   - 编译运行，发现 MSG3 缺少调度请求机会时，查看日志返回修改 MAC 调度器，
   - 最终测试通过，更新技能完成报告。

## 总结

**通过分层技能驱动 agent 实现无线通信系统，本质上是把人脑中的系统架构和经验，转译成 agent 能逐步消化、执行、验证的“技能积木”。** 你的工作从一行行写代码，转变为：定义接口、编写技能卡片、设计验证准则、审核 agent 的产出和流程。

这个方法论一旦建立，不仅能让 Claude Code 实现一个 5G 基站或终端协议栈，更能成为你们团队长期可复用的“AI 原生系统工程能力”。
