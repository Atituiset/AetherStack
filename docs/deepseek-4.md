## 🏗️ 三环架构总览

```
┌─── Web LMT (TypeScript) ─────────────────────────┐
│  实时状态面板 | 消息序列图 | PDU 十六进制查看器    │
└──────────────┬────────────────────────────────────┘
               │ WebSocket (实时状态/事件)
┌──────────────▼────────────────────────────────────┐
│  调试与工具层 (Python)                             │
│  信道仿真 | 日志收集解析 | WebSocket 推送服务器     │
│  MSC 生成 | 自动化测试 | 参考模型                  │
└──────────────┬────────────────────────────────────┘
               │ UDP/共享内存 (日志、状态、IQ数据)
┌──────────────▼────────────────────────────────────┐
│  协议栈 (C++)                                     │
│  UE 进程 | BS 进程 | NAS/AS/L1 各层实体           │
└───────────────────────────────────────────────────┘
```

- **C++ 层**：只做协议处理和实时数据流，通过统一日志接口向外输出结构化事件（JSON 或 protobuf）。
- **Python 层**：不参与协议逻辑，负责信道仿真、日志汇聚、测试编排，并作为 WebSocket 服务端向 Web 推送状态。
- **TypeScript 层**：纯前端，订阅 WebSocket 流，渲染成“活”的 UE/BS 模拟视图。

### 第 1 阶段：物理层最小闭环（C++ + Python 参考模型，2 周）
（与之前计划基本一致，但需在关键节点向 Python 发送状态事件）

- M1.1 ~ M1.4：实现 QPSK、OFDM 收发，**每个技能要求 C++ 在完成解调后发送一次 `PHY_RX_OK` 事件（JSON）**。
- Python 参考模型用于验证，同时 Python 日志服务将 `PHY_RX_OK` 转发到前端，前端能点亮一个“L1 同步”指示灯。

---

### 第 2 阶段：MAC 随机接入（3 周）

- 状态机每改变一次状态，C++ 立即发送 `MAC_STATE_CHANGE` 事件，包含状态名。
- 前端收到后，可显示 UE 和 BS 的 MAC 状态机实时状态。

---

### 第 3 阶段：RLC / PDCP 透传（1 周）

- 增加 PDU 边界事件：每层在收发 PDU 时发送 `PDU_TRACE` 事件（含原始十六进制）。
- Python 层可以缓存这些事件，并提供一个 WebSocket API，让前端按需请求某次连接的完整 PDU 链。
