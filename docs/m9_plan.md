## M9: FEC + HARQ（详细设计）

### D1 信道编码 — 卷积码 K=7, rate 1/2

* 生成多项式 `G1=133o, G2=171o`（业界经典 NASA 标准），尾比特归零收尾
* 译码：Viterbi 硬判决（路径度量汉明距离），回溯窗口 ≥ 5×K
* 编码增益验证：AWGN 下 BER 曲线单测对比编码/未编码

### D2 完整性 — CRC16-CCITT

* 每个 HARQ 传输块附 CRC16；译码后校验决定 ACK/NACK
* CRC 失败的块**不递交上层**（此前 TM 时代坏块直接穿透）

### D3 HARQ — 停等式 (SAW) 多进程

* 帧头扩展：DATA air frame 的 MAC PDU 前加 HARQ 子头
  `[proc:2][ndi:1][rv:2][len:3 LE]`（8 字节定长）
* 接收端 CRC OK → 回 ACK 并递交；CRC FAIL → 缓存软信息（此处简化为
  缓存原始比特），回 NACK；发送端收到 NACK 重传同一块（Chase 合并：
  对应位置比特多数表决合并两次尝试）
* 反馈通道：ACK/NACK 作为独立 LCID (60) 的控制 PDU，走对向 DATA 帧
* 多进程：4 个并行 HARQ 进程轮转，支持连续发送不空等
* 上层语义不变：RLC/App 不感知重传，应用层丢失率在可恢复信道下归零

### DoD

1. FEC 单测：无噪往返全过；AWGN SNR 扫描 BER 曲线显示明确编码增益
2. Viterbi 极限测试：随机翻转 ≤15% 比特全部纠回
3. HARQ 单测：30% 帧级丢弃 + 比特翻转混合注入，最终零错误递交
4. E2E：channel loss 20% 下应用层 loss==0（M7.4 同场景从"有损"变"无损"）
5. 全量回归 93+ 用例双构建通过
